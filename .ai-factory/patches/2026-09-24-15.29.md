# Output reverted from JSON arrays to one file per resource

**Date:** 2026-09-24 15:29
**Files:** internal/storage/storage.go, internal/extractor/extractor.go, cmd/asana-extractor/main.go, cmd/asana-extractor/main_test.go, internal/storage/storage_test.go, internal/extractor/extractor_test.go, README.md
**Severity:** medium

## Problem

After the switch to `output/users.json` / `output/projects.json` arrays, the user asked for the original layout back: one JSON object per user and per project (`output/<kind>/<gid>.json`), which is also what the exercise spec requires.

## Root Cause

A requirements reversal. The previous change (patch 2026-09-24-15.21) replaced a spec-mandated behavior on request without the spec itself changing. The only commit contained the array version, so git could not restore the per-file code, and it had to be rebuilt.

## Solution

- Restored `Store.Put(kind, gid, v)`: GID validated before use as a filename, JSON goes to a temp file in `<dir>/<kind>/`, then fsync and rename. Identical content is skipped, and the temp file is removed on failure.
- `CleanupTemp(olderThan)` scans the kind directories again.
- The extractor writes each resource as its page arrives. Per-file saves are now logged at debug level, since there can be thousands per run.
- Kept the `asanatest.FailAfter` helper and used it for a new per-file-consistency test: page 1 files stay when page 2 fails.

## Prevention

- Before changing a behavior the spec requires, note the deviation in the plan and commit the spec-compliant version first, so a revert is one `git revert`.
- Keep the regression test pinned to the exact on-disk layout (directory listing plus file shape); that made both switches fail loudly.
